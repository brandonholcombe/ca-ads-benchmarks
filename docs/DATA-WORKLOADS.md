# Bounded M05/M09 data workloads

`nca_ads_bench.data_workloads` defines three additional `Case` objects for the existing benchmark runner. They are synthetic exercises, not measurements of a course lesson or a claim of GPU speedup. CPU generation and references need only NumPy and pandas. GPU cases additionally need CuPy, cuDF, and, for the graph case, cuGraph in a compatible NVIDIA environment. `dependency_versions(gpu=True)` imports all three and reports their versions; missing packages raise an error. GPU execution has not been validated on this authoring Mac.

| Case | Input and operation | Complete correctness check |
|---|---|---|
| `eda_summary_stats` | `rows` seeded float32 observations; NaNs and deliberate finite outliers. This EDA summary is a NumPy/CuPy histogram of 32 equal bins over `[0, 1]`, ignoring NaNs and values outside that range. The last bin includes 1. | All 32 integer counts exactly and all 33 edges within absolute `1e-7`; a matching total alone is insufficient. |
| `chronological_rolling_mean` | `rows` seeded observations with unique, irregular integer minute offsets, shuffled on input. pandas/cuDF sort by minute and compute a **trailing eight-observation** mean, requiring at least three nonmissing values. This is row-based, not an eight-minute clock window. Null input values do not count toward the minimum. | Every sorted minute, every null position and every mean (`rtol=atol=1e-10`). A later observation never enters an earlier window. |
| `directed_graph_degree` | `rows` unique, loop-free directed edges with contiguous integer vertex IDs, for 100–100,000 edges. The graph includes a sink with incoming edges and zero outgoing edges. pandas groups source/destination counts; cuGraph builds a directed graph and returns each vertex's in- and out-degree. | Every external vertex ID and both degrees exactly after sorting by ID. Order of cuGraph's result rows is irrelevant; comparing totals alone would miss a wrong mapping. |

All three case factories accept 100–100,000 rows. The graph size bound keeps default 10,000 and larger 100,000 row runs cheap. Requests outside 100–100,000 edges fail visibly; they are never silently capped. The graph output includes vertices that occur in at least one edge, including the sink; it does not include imaginary isolated vertices. IDs are contiguous, so `renumber=False` is valid and avoids an unnecessary internal-to-external ID mapping. Graph degree counts edges separately by direction; a sink can have positive in-degree with zero out-degree. The generated graph has no duplicate edges or self-loops, so simple-graph semantics are unambiguous.

Each `Case` uses the repository's existing timing boundaries: CPU host input to host output, GPU resident input to device output, and GPU host-to-host including conversion and transfer. Input generation, comparison and imports remain outside the timer. Graph construction is part of the degree operation, on both CPU and GPU paths. The runner records raw timing samples and dependency versions; a failed comparison prevents a speedup claim. A CPU test or mock does not establish GPU correctness; run the exact revision on the allocated Blackwell device before reporting GPU results.

API references checked 2026-09-29: [CuPy histogram](https://docs.cupy.dev/en/stable/reference/generated/cupy.histogram.html) documents fixed bins, range filtering and returned counts/edges; [cuDF rolling](https://docs.rapids.ai/api/cudf/stable/user_guide/api_docs/api/cudf.series.rolling/) documents trailing windows and `min_periods`; [cuGraph edge-list construction](https://docs.rapids.ai/api/cugraph/stable/api_docs/api/cugraph/cugraph.graph.from_cudf_edgelist/) documents `renumber=False` for contiguous IDs; [cuGraph degrees](https://docs.rapids.ai/api/cugraph/nightly/api_docs/api/cugraph/cugraph.structure.graph_implementation.simplegraphimpl.degrees/) documents vertex IDs and directed in/out-degree output. The installed 26.08 container API and behavior still require remote GPU validation.
